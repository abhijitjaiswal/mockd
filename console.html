Keeping it honest

You cannot stop someone opening an old export on their own machine — and you should not try, because comparing old against new is a legitimate way to prove a regression. What this does is make it impossible to do silently, and impossible to land in CI.

1. Content addressNothing is “the spec”. It is always the spec with digest abc123…, normalised so re-exports with different key order are not false alarms.
2. A committed lockspec.lock.json records the digest, source, time and operation count. Changing spec changes the lockfile, which shows up as a diff in review — the trick package-lock.json uses.
3. CI re-fetches and compares speclock.py check pulls from the recorded source and exits non-zero if the digest moved. Upstream changing is fine; it just has to be re-locked on purpose.
4. Every result is stampedTest and verify reports carry the digest they ran against, so “these passed” is always “these passed against document X”.
5. Fewer operations is loudAn older export is mostly removals. The check says so in those words rather than leaving you to notice.
6. Comparing is supportedRun the suites against two documents on purpose with speclock.py diff — so nobody needs to smuggle an old spec in to prove a point.
